# 可用性校验与测速筛选（P0/P1）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现质量子系统的 P0/P1：三级规则、可达性/清单/测速探测、内存结果、订阅隐藏与恢复、手动与周期任务、设置页与分组页徽章。

**Architecture:** 新增 `[quality]` 配置段与 `src/quality/` 模块。调度器按 `next_check_at` 轮转频道，探测器按档位读取 HLS 或连续流，结果写入紧凑内存快照。订阅渲染只读该快照，按有效规则隐藏不合格频道。质量关闭时，现有健康探测与订阅输出保持不变。

**Tech Stack:** Rust 2021、axum 0.7、reqwest 0.12、tokio、serde、React + TypeScript、Vite。

**Spec:** `docs/design/13-availability-and-speedtest.md`

## Global Constraints

- 默认 `quality.enabled=false`。关闭时订阅清单字节级不变。
- 第一版覆盖托管源同步频道与手工频道。聚合源不校验，归档组不校验。
- 隐藏只影响订阅渲染。直接播放地址不返回 404。
- 没有结果、结果地址不匹配、`probe_error` 均不隐藏。
- 失败宽限从 `first_fail_at` 起算。默认 `stale_keep_secs=1800`，单次失败不下线。
- 内存只存紧凑快照。禁止缓存媒体样本与完整清单。
- 单轮受 `budget_mb_per_run`、`max_channels_per_run`、`concurrency` 限制。
- 所有新配置字段必须有 `#[serde(default)]` 默认值。未知键保留在 `extra`。
- 中文注释与文档。按 80% ASD-STE100：短句、主动语态、一句一义。
- 本计划不实现：SQLite 结果与历史、源自动停用、`ffprobe`、广告过滤、同组去重、固定保留、聚合源校验。这些属于 P2/P3。
- P1 手动校验与已有校验任务冲突时返回 `409 run_active`。与订阅同步的排队在 P2 补。
- P1 一频道一地址，`run_mode=quick` 与 `full` 行为相同。`run_mode` 字段保留，供 P3 去重使用。
- `probe_mode=full` 在 P1 按 `speed` 执行。`filter_ad`、`host_cache`、`quick_target`、`sort_by`、`defer_during_playback` 字段保留，但 P1 不生效。

## Review Focus

- `quality.enabled=false` 或没有结果时，订阅清单与现在完全一致。
- `probe_error`、地址变化、结果缺失时保持可见，不能误隐藏。
- 单次失败不隐藏。连续失败从第一次失败起算，超过宽限才隐藏。
- `passthrough`、归档组、聚合源不参与隐藏。
- 预算或并发耗尽时停止发起新任务，已完成结果保留，现有清单不被误改。

- [ ] **Step 7: Implement `evaluate`**

顺序：

1. `retain` → `Retained`，`ok=true`。
2. `probe_error` → `ProbeError`，`ok=false`。上层不隐藏。
3. `!reachable` → `Unreachable`，`ok=false`。
4. 分辨率已知且低于下限 → `ResolutionLow`。
5. 分辨率已知且高于上限 → `ResolutionHigh`。
6. 速率低于 `resolution_speed_map` 对应值或 `min_speed_mib` → `SpeedLow`。
7. 延迟高于 `max_delay_ms` → `DelayHigh`。
8. `supply` 且此前有阈值失败 → `Supply`，`ok=true`。
9. 否则 `Pass`，`ok=true`。

`resolution_speed_map` 先按键的像素数从高到低找第一个 `<=` 当前分辨率的项。没有命中时用 `min_speed_mib`。

    path: &'static str,
    content_type: &'static str,
    body: String,
    status: &'static str,
) -> String {
    use tokio::io::{AsyncReadExt, AsyncWriteExt};
    let listener = tokio::net::TcpListener::bind("127.0.0.1:0").await.expect("bind");
    let addr = listener.local_addr().expect("addr");
    tokio::spawn(async move {
        let (mut socket, _) = listener.accept().await.expect("accept");
        let mut buf = [0u8; 1024];

            body.len()
        );
        let _ = socket.write_all(response.as_bytes()).await;
    });
    format!("http://{addr}{path}")
}

- [ ] **Step 7: Implement `probe`**

流程：

1. `client.get(url).headers(...)`，超时 `limits.timeout`。
2. 非 2xx → `reachable=false`，`error=Some("HTTP <code>")`。
3. `ProbeMode::Reachability`：读完首字节或状态后返回。`speed_mib=None`，`duration_ms` 为请求耗时。
4. 读取正文，最多 `max_playlist_bytes`。
5. 判断 HLS：地址含 `.m3u8`、`Content-Type` 匹配、或正文以 `#EXTM3U` 开头。
6. 主清单：`parse_master(body, base, max_resolution_px)`。成功则取变体地址，再次读取媒体清单（受 `max_playlist_bytes`）。失败 → `probe_error`。
7. 媒体清单：`parse_media_segments`。为空 → `probe_error`。
8. `ProbeMode::Playlist`：解析成功后返回。`speed_mib=None`。不下载切片。
9. `ProbeMode::Speed`：逐切片读取，受 `max_sample_bytes` 与 `max_sample_secs` 限制。统计总字节与总耗时。速度 = 总字节 / 总耗时 / 1024 / 1024。延迟 = 首个切片首字节时间。
10. 非 HLS 且 `ProbeMode::Speed`：按第 9 步直接测速。正文已读入，计入字节。
11. 任何网络错误 → `reachable=false`，`probe_error=false`。解析错误 → `reachable=true`，`probe_error=true`，`error=Some(...)`。
12. 返回值包含 `measurement`、`bytes`、`duration_ms`。

`ProbeOutput` 的 `measurement.probe_error` 在解析错误时为真。上层据此判 `Reason::ProbeError`，不隐藏。

- [ ] **Step 7: Implement target selection and scheduler**

`target_channels`：

- 遍历 `config.groups`。
- 跳过 `access == "archived"`。
- 跳过 `mode == "passthrough"` 且 `!config.quality.probe_passthrough`。
- `force=false` 时对每个频道调用 `effective_rules`。`enabled=false` 时跳过。`force=true` 时忽略质量启用状态，只跳过归档组与不应探测的直通组。
- 返回 `(gid, cid, Channel)`。

`run_limit`：

- `budget_mb == 0` 或 `per_channel_mb <= 0` → `max_channels`（0 表示 `usize::MAX`）。
- 否则取 `floor(budget_mb / per_channel_mb)` 与 `max_channels`（0 表示不限）的较小值。
- P1 用固定估算 `per_channel_mb=8.0`。P2 用实测平均值。

`spawn`：

- 启动后等待 60 秒。
- 每 60 秒检查一次。
- `config.quality.enabled=false` 时跳过。
- `interval_secs == 0` 时只处理手动任务。
- 计算到期频道：`Entry.next_check_at <= now` 或没有 Entry。
- 按 `next_check_at` 升序排序，应用 `run_limit(budget_mb_per_run, 8.0, max_channels_per_run)`。
- 使用 `tokio::sync::Semaphore` 限制 `concurrency`。
- 每个频道：
  1. 解析地址：`resolver::resolve`。`Ok(Some(url))` 用它；`Ok(None)` 用 `channel.url`；`Err` 写 `Reason::ProbeError`，不发起请求。
  2. 取 `effective_rules(&config, group, channel)`。合并 `channel_headers`，取 `state.probe_client_for(gid,cid)` 作为客户端。
  3. 由全局配置构造 `ProbeLimits`：
     - `timeout = timeout_secs`
     - `speed_timeout = speed_timeout_secs`
     - `max_playlist_bytes = max_playlist_kb * 1024`
     - `max_sample_bytes = sample_bytes_kb * 1024`
     - `max_sample_secs = sample_secs`
     - `sample_segments = sample_segments`
  4. 调用 `probe(&client, &url, &headers, mode, rules.max_resolution_px, &limits)`。模式映射：`reachability` → `Reachability`，`playlist` → `Playlist`，`speed` / `full` → `Speed`。
  5. 调用 `evaluate`。
  6. 写 `QualityState`：`url_hash=url_hash(&channel.url)`；`first_fail_at` 在 `verdict.ok == false` 且 `reason != ProbeError` 时设置；`consecutive_fails` 同样递增。成功、`Retained`、`Supply` 清空 `first_fail_at` 并清零失败计数。`probe_error` 不改失败计数与 `first_fail_at`。`next_check_at` 按退避。
     - 失败 1–2 次：`now + interval_secs`。
     - 失败 3 次起：`now + max(interval_secs, min(86400, 60 * 2^consecutive_fails))` 秒。
     - 成功或 `probe_error`：`now + interval_secs`。`probe_error` 不增加失败计数。
  7. 调 `state.health.record(...)`：`ok = measurement.reachable`，`error` 仅 `unreachable` 时写，`http_status`/`latency_ms` 透传。`probe_error` 时不写 `Health`，保留上一次值。
  8. 累加 `bytes`。达到预算 90% 后停止发起新任务。
- 进度写入 `QualityState.run`。

`run_now`：

- `try_start_run` 失败 → `RunError::Busy`。
- 选择目标：按 `RunScope` 过滤 `target_channels(&config, force)`。
- 忽略 `next_check_at`（`force=true`）或遵守。
- 启动任务，返回 `run_id`。
- 任务结束后调用 `finish_run`。
