# 低配与高配环境的运行参数差异

> 写作风格：ASD-STE100 简化技术写作。一句一个意思。主动语态。用简单现在时。
> 部署步骤与 CDN 控制台见 [`18-low-spec-deployment.md`](18-low-spec-deployment.md)。

## 1. 结论

安装脚本的 `--low-spec` 写入 5 个键。

| 键 | 默认（常规） | 低配 | 作用 |
| --- | --- | --- | --- |
| `cache.segments.per_channel_max` | `0`（内置 4096） | `200` | 每频道切片索引条数上限。降低内存占用 |
| `cache.prefetch.concurrency` | `4` | `2` | 预取并发。降低开播与切台的 CPU 峰值 |
| `auth.token_enabled` | `true` | `true` | 播放凭证。每台设备只能播放授权频道 |
| `auth.ip_guard_enabled` | `true` | `true` | IP 限流、播放会话上限与封禁 |
| `cdn.enabled` | `false` | `true` | 外部 CDN 未生效时，本机补齐缓存头与错误状态 |

只有前 2 个键属于减负。

后 2 个鉴权键默认已开启。安装脚本仍显式写入，便于已有数据库补齐。

`cdn.enabled` 也从默认值改变，但它打开功能，不降低负载。

`cache.segments.per_channel_max` 只限制索引条数，不限制磁盘空间。
`cache.prefetch.concurrency` 控制同时在途的预取请求数。
两个鉴权键改变访问控制行为，不省资源。

低配示例 `config-low-spec.json` 还显式写出多个默认值。作用只是文档，不是调优。

`[server].low_resource_mode` 低配示例没有设置。它只出现在 `/api/panel/status` 的回显里，
不改变任何行为（复刻目标行为）。不要把它当调优开关。

## 2. 按资源类型看参数

### 2.1 内存

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `cache.segments.per_channel_max` | `0` = 内置 4096 | 每个频道的切片索引条数上限。低配设 200 |

低配示例把 `per_channel_max` 压到 200。按 40 个频道算，进程内索引约 40 × 200 × 558 B ≈ 4.5 MB。
进程内索引按 600 秒活动窗口淘汰。配置里没有索引总量键。
`cache.limit_mb` 是磁盘键，见 §2.3。

### 2.2 CPU

| 键 | 默认 | 低配 | 作用 |
| --- | --- | --- | --- |
| `cache.prefetch.concurrency` | `4` | `2` | 预取并发。开播瞬间的 CPU 峰值由它决定 |
| GC 单轮扫描数 | 固定推导 | `clamp(上限 MB / 4, 500, 5000)`，不可配置 |
| `cache.dash.fetch_concurrency` | `20` | 未调 | DASH 切片并发 |
| `health.concurrency` | `3` | 未调 | 健康探测并发 |

1 vCPU 上真正要压的是 `prefetch.concurrency`。DASH 的 `fetch_concurrency = 20`
只影响 DASH 组，低配环境通常不开 DASH。

### 2.3 磁盘

| 键 | 默认 | 低配 | 作用 |
| --- | --- | --- | --- |
| `cache.limit_mb` | `0` = 自动 | `0` | `0` 时按「可用空间 × 0.8 − 100 MB」与工作集取小；非 0 为手动值 |
| `cache.gc.max_age_secs` | `1800` | `1800` | 切片最长存活；`0` = 不按时间删除 |

磁盘回收常开，没有开关。扫描周期固定 60 秒。预留 100 MB，自动上限下限 50 MB，
总量上限为文件系统的 70%。

没有不生效的兼容键。`[cache]` 只保留 `per_channel_max` 与 `limit_mb` 两个容量相关键。

### 2.4 网络与上游

| 键 | 默认 | 低配示例 | 作用 |
| --- | --- | --- | --- |
| `cdn.enabled` | `false` | `true` | 外部 CDN 侧兜底 |
| `cache.auto_tune` | `true` | `true` | 被动采样 TTL 与切片体积。有少量后台开销 |
| `health.enabled` | `true` | 未设 | 周期探测所有频道上游 |
| `health.interval_secs` | `300` | 未设 | 探测周期 |

低配环境的上游请求预算很紧。健康探测每 300 秒对所有频道打一次上游，
频道多时这是可观的额外请求。

### 2.5 后台任务（功能级）

这些不靠参数调优，靠**关掉整个功能**才省得下来。

| 功能 | 开销 | 是否有开关 |
| --- | --- | --- |
| 定时录制 | ffmpeg 子进程，持续转封装，磁盘写入 | 无（只能不创建任务） |
| 回看缓冲（`livestream`） | 每个开机频道持续抓取切片并落盘 | 无（只能不点亮） |
| DASH 时移（`dash_timeshift`） | 逐轨道抓切片，磁盘与网络双高 | 无 |
| 台标动效 | 一次性 CPU 峰值 | 无 |
| EPG 采集 | 周期拉取和解析 XMLTV | `epg.enabled` |
| EPG 翻译 | 批量 HTTP 调用 | `epg.translate.enabled` |
| 字幕翻译 | 按需 HTTP 调用 | `subtitle.translate.enabled` |
| 多 VPS 分享 | 周期轮询对端 | `share.enabled` |

## 3. 对功能开关的启示

低配环境最需要能关掉的是 **§2.5 里没有开关的三项**：定时录制、回看缓冲、DASH 时移。

它们的特点是：

1. 一旦启用就持续占用 CPU 与磁盘。
2. 没有全局开关，只能逐频道设置。
3. 面板上没有统一的入口。

次要项是健康探测。它已经有 `health.enabled`，缺的是面板上的入口。

反过来，**切片缓存、预取、GC 这些不该做成开关键**。它们是播放链路的一部分。
关掉预取只会让每次重连都回源，反而更慢。调 `concurrency` 就够了。

## 4. 建议的面板开关清单

| 开关 | 控制的配置 | 为什么值得放面板 |
| --- | --- | --- |
| 定时录制 | `[features].recording` | ffmpeg 是最大开销 |
| 回看缓冲 | `[features].livestream` | 持续录制，磁盘杀手 |
| 频道探测 | `[health].enabled` | 已有配置 |
| 节目指南 | `[epg].enabled` | 已有配置 |
| 分享 | `[share].enabled` | 已有配置 |

前两项是 2026-10-31 新增的键。后三项原本就有。

统一语义：关闭后分区入口消失，接口返回 `403`。
与部署规格无关 —— 高配与低配行为一致，不做「低配才拦截」的分支。

## 5. 手动覆盖自适应参数

系统会按 §2 的公式自动算三个量。其中两个可以手动覆盖。

### 5.0 已安装用户切换为低配

用面板。保存后立即替换运行配置，不需要重启。

| 顺序 | 面板路径 | 改为 |
| --- | --- | --- |
| 1 | 系统设置 → 缓存与回收 → 高级设置 → 单频道索引条目上限 | `200` |
| 2 | 系统设置 → 缓存与回收 → 高级设置 → 预载配置 → 拉取并发 | `2` |
| 3 | 系统设置 → 分发与伪装 → CDN 兜底 → 启用 CDN 兜底 | 开启 |
| 4 | 安全管控 → 访问与链接 → IP 管控 | 开启 |
| 5 | 安全管控 → 访问与链接 → 播放凭证 | 开启 |

只想省资源时，做前 2 项。

已有数据库保留原值。默认值只影响新建配置。

默认 `auth.max_sessions_per_ip = 1`。同一出口 IP 同时只保留 1 路播放会话。
多人共用网络时改大。

不要使用「系统设置 → 基础运行 → 服务器 → 低配模式」。它只回显，不改变参数。

新装时，安装脚本默认询问是否使用低配参数。加 `--low-spec` 跳过询问：

```sh
sudo ./install.sh --low-spec
```

脚本写入 5 个键。其中前 2 个用于减负。

### 5.1 磁盘上限（可直接覆盖）

面板路径：**系统设置 → 缓存与回收 → 缓存容量与回收 → 缓存上限**。
配置键 `cache.limit_mb`。

填 `0` 时走公式。填非 0 时直接使用该值，公式不参与。

代码位置：`src/cache_gc.rs` 的 `cap_plan`。第一行就是
`if explicit_mb != 0 { return ... }`。

公式常量不再外露：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| 可用空间比例 | `0.8` | 自动上限最多占可用空间的 80% |
| 磁盘预留 | `100 MB` | 给系统留的余量 |
| 最小上限 | `50 MB` | 上限的下限 |

生效时机：保存后下一轮 GC 生效。GC 周期固定 60 秒。

### 5.2 工作集（不能直接改）

工作集是实测值，不是配置项。面板没有输入框。

公式：`round10(working_channels × N × 切片体积MB × 1.5)`。
`working_channels = max(3, 最近一个在线窗口内活动的频道数)`。`N` 来自最近一次实测的窗口切片数。

想让它变小，只能间接影响：

- 减少同时开播的频道数。
- 缩短 DASH 清单窗口（`cache.dash.playlist_min_secs`）。
- 降低上游码率。

### 5.3 TTL 推荐值（只读，可用固定值替代）

「缓存状态」页显示实测推荐的切片 TTL。那个值给 CDN 控制台用，不是本机配置。

本机想固定 TTL，改 **系统设置 → 缓存与回收 → 缓存有效期 → 切片有效期**（`cache.ttl.segment_secs`）：

| 值 | 行为 |
| --- | --- |
| `0` | 用实测推荐值；无数据时 600 秒 |
| `300` | 固定 300 秒 |

手动值在 CDN 开/关下都生效。

### 5.4 其它可覆盖项

| 量 | 面板位置 | 配置键 |
| --- | --- | --- |
| 每频道索引条数 | 系统设置 → 缓存与回收 → 高级设置 → 单频道索引条目上限 | `cache.segments.per_channel_max` |
| 预取并发 | 系统设置 → 缓存与回收 → 高级设置 → 预载配置 → 拉取并发 | `cache.prefetch.concurrency` |
| 切片最长存活 | 系统设置 → 缓存与回收 → 缓存容量与回收 → 过期删除 | `cache.gc.max_age_secs` |

### 5.5 常见操作

低配机器强制压到 80 MB：

```
系统设置 → 缓存与回收 → 缓存容量与回收 → 缓存上限 = 80 → 保存
```

查看公式当前算出多少、工作集多大：**缓存状态**页的「本机缓存」卡片。
「CDN 推荐值」卡片上的「立即估算」可按需重新采样，同时刷新本机上限。

### 5.6 总表

| 自适应量 | 能否覆盖 | 入口 |
| --- | --- | --- |
| 磁盘上限 | 是，直接覆盖 | 系统设置 → 缓存与回收 → 缓存容量与回收 → 缓存上限 |
| 公式参数 | 否 | 固定常量 |
| 工作集 | 否 | 无入口，只能间接影响 |
| 实测 TTL | 否，可用固定值替代 | 系统设置 → 缓存与回收 → 缓存有效期 → 切片有效期 |
| 每频道索引条数 | 是 | 系统设置 → 缓存与回收 → 高级设置 → 单频道索引条目上限 |
| 预取并发 | 是 | 系统设置 → 缓存与回收 → 高级设置 → 预载配置 → 拉取并发 |
