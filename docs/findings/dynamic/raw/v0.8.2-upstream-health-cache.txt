## D21.3 上游恢复 / 上游再故障（同频道，不清缓存）

频道 `gfm/m5` → `9969/x.m3u8`。

| 步骤 | 上游状态 | 入口 HTTP |
| --- | --- | --- |
| 1 | 9969 无监听（拒连） | **302** |
| 2 | 9969 有服务但无 `x.m3u8`（404） | **302** |
| 3 | 放入 `x.m3u8`（未清缓存） | **200**（同一秒内恢复，切片 200/262144） |
| 4 | 移走 `x.m3u8` 后第 1 次 | 200（旧清单缓存仍在） |
| 5 | 移走后第 2 次（+3s） | 200 |
| 6 | 移走后第 3 次（+6s） | **302** |

```console
$ cat 9969.log
1792322741.677 GET 200 /x.m3u8 …    # 步骤 2 的失败探测
1792322741.680 GET 404 /x.m3u8 …    # (同一个请求，见日志工具说明)
1792322741.718 GET 200 /x.m3u8 …    # 步骤 3
1792322741.723 GET 200 /seg2.ts …
1792322741.723 GET 200 /seg1.ts …
$ for i in 1 2 3; do curl -s -o /dev/null -w "第${i}次 entry HTTP %{http_code}\n" "$B/gfm/m5.m3u8"; sleep 3; done
第1次 entry HTTP 200
第2次 entry HTTP 200
第3次 entry HTTP 302
```

→ **失败不缓存，恢复立即生效；成功清单缓存 ~5s**（与入口 `cache-control: max-age=5` 一致）。
